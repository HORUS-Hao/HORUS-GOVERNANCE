## 一、Purpose

本文件定義 T002 狀態轉換的 Gate 規格，用於：

- 明確狀態轉換的必要條件
- 定義每個 Gate 的禁止事項
- 作為未來狀態機實作的依據

**本文件僅定義規則，不涉及流程或介面。**

---

## 二、Gate 總覽

### 2.1 關鍵轉換路徑

```
INCOMPLETE ──[Gate-A]──> WAITING_*
WAITING_* ──[Gate-B]──> PENDING_AI_CLEAN
PENDING_AI_CLEAN ──[Gate-C]──> AI_CLEANING
AI_CLEANING ──[Gate-D]──> PENDING_HUMAN_CONFIRM / READY_FOR_T005
PENDING_HUMAN_CONFIRM ──[Gate-E]──> READY_FOR_T005
READY_FOR_T005 ──[Gate-F]──> T005_TRANSFERRING
T005_TRANSFERRING ──[Gate-G]──> LOCKED_AFTER_T005
```

### 2.2 Gate 清單

| Gate ID | 轉換 | 重要性 |
|---------|------|--------|
| Gate-A | INCOMPLETE → WAITING_* | 中 |
| Gate-B | WAITING_* → PENDING_AI_CLEAN | 中 |
| Gate-C | PENDING_AI_CLEAN → AI_CLEANING | 低 |
| Gate-D | AI_CLEANING → 下一狀態 | 高 |
| Gate-E | PENDING_HUMAN_CONFIRM → READY_FOR_T005 | **關鍵** |
| Gate-F | READY_FOR_T005 → T005_TRANSFERRING | **關鍵** |
| Gate-G | T005_TRANSFERRING → LOCKED_AFTER_T005 | **關鍵** |

---

## 三、Gate-A：INCOMPLETE → WAITING_*

### 3.1 通過條件

| 條件 | 說明 | 驗證方式 |
|------|------|----------|
| 缺失欄位已識別 | 明確哪些欄位缺失 | 欄位檢查 |
| 責任方已判定 | 明確由誰負責補齊 | 責任判定規則 |
| 目標狀態已決定 | WAITING_SUPPLIER / BRAND / INTERNAL | 責任對應 |

### 3.2 禁止事項

| 禁止行為 | 原因 |
|----------|------|
| 未判定責任即轉換 | 無法追蹤 |
| 跳過直接到 READY | 資料不完整 |
| 多責任方同時分派 | 責任不明 |

---

## 四、Gate-B：WAITING_* → PENDING_AI_CLEAN

### 4.1 通過條件

| 條件 | 說明 | 驗證方式 |
|------|------|----------|
| 缺失欄位已補齊 | 所有缺失欄位有值 | 欄位檢查 |
| 資料格式正確 | 符合欄位格式要求 | 格式驗證 |
| 來源已記錄 | 補齊資料來源明確 | 欄位檢查 |

### 4.2 禁止事項

| 禁止行為 | 原因 |
|----------|------|
| 部分補齊即通過 | 資料仍不完整 |
| 無來源記錄 | 無法追溯 |
| 格式錯誤強制通過 | 後續清洗失敗 |

---

## 五、Gate-C：PENDING_AI_CLEAN → AI_CLEANING

### 5.1 通過條件

| 條件 | 說明 | 驗證方式 |
|------|------|----------|
| 清洗程序已就緒 | 清洗規則可用 | 系統狀態 |
| 無其他程序占用 | 無衝突 | 系統狀態 |

### 5.2 禁止事項

| 禁止行為 | 原因 |
|----------|------|
| 清洗規則未更新即啟動 | 結果不正確 |
| 同一記錄重複清洗 | 資源浪費 |

---

## 六、Gate-D：AI_CLEANING → 下一狀態

### 6.1 分支條件

| 情況 | 目標狀態 | 條件 |
|------|----------|------|
| 清洗成功＋高信心度 | READY_FOR_T005 | 信心度 ≥ 閾值 |
| 清洗成功＋低信心度 | PENDING_HUMAN_CONFIRM | 信心度 < 閾值 |
| 清洗發現缺失 | INCOMPLETE | P0/P1 欄位缺失 |

### 6.2 通過條件（到 READY_FOR_T005）

| 條件 | 說明 | 驗證方式 |
|------|------|----------|
| 清洗程序完成 | 無錯誤 | 程序回報 |
| 信心度達標 | ≥ 設定閾值 | 信心度欄位 |
| P0/P1 欄位完整 | 無缺失 | 欄位檢查 |
| 標準化欄位有值 | 名稱/品牌/型號 | 欄位檢查 |

### 6.3 禁止事項

| 禁止行為 | 原因 |
|----------|------|
| 忽略低信心度直接 READY | 品質風險 |
| 忽略缺失直接 READY | 資料不完整 |
| 清洗失敗強制通過 | 資料錯誤 |

---

## 七、Gate-E：PENDING_HUMAN_CONFIRM → READY_FOR_T005（關鍵）

### 7.1 通過條件

| 條件 | 說明 | 驗證方式 |
|------|------|----------|
| 人工確認人已填 | 明確確認者 | 欄位非空 |
| 確認日期已填 | 明確確認時間 | 欄位非空 |
| 標準化欄位已確認 | 名稱/品牌/型號 | 值非預設 |
| 確認人有權限 | 非任意人員 | 權限檢查 |

### 7.2 禁止事項

| 禁止行為 | 原因 | 後果 |
|----------|------|------|
| 無確認人即通過 | 責任不明 | **Gate 阻斷** |
| 自動填入確認人 | 規避流程 | **Gate 阻斷** |
| 系統帳號確認 | 非人工確認 | **Gate 阻斷** |
| 跳過確認直接 READY | 品質風險 | **Gate 阻斷** |
| 批次自動確認 | 規避流程 | **Gate 阻斷** |

### 7.3 確認內容要求

| 確認項目 | 必須確認 |
|----------|----------|
| 標準化名稱正確 | ✅ 是 |
| 標準化品牌正確 | ✅ 是 |
| 標準化型號正確 | ✅ 是 |
| 與原廠資料一致 | ✅ 是 |

---

## 八、Gate-F：READY_FOR_T005 → T005_TRANSFERRING（關鍵）

### 8.1 通過條件

| 條件 | 說明 | 驗證方式 |
|------|------|----------|
| 所有 P0 欄位完整 | 無缺失 | 欄位檢查 |
| 所有 P1 欄位完整 | 無缺失 | 欄位檢查 |
| AI清洗狀態 = 完成 | 清洗已完成 | 狀態欄位 |
| 人工確認完成（若需要） | 低信心度已確認 | 確認欄位 |
| T005 可接收 | T005 狀態正常 | T005 狀態 |
| 無重複記錄 | T005 無相同商品 | T005 查詢 |

### 8.2 禁止事項

| 禁止行為 | 原因 | 後果 |
|----------|------|------|
| P0/P1 缺失強制轉入 | 資料不完整 | **Gate 阻斷** |
| 未確認強制轉入 | 品質風險 | **Gate 阻斷** |
| T005 異常時轉入 | 資料遺失風險 | **Gate 阻斷** |
| 重複記錄轉入 | 資料污染 | **Gate 阻斷** |
| 批次轉入未檢查 | 品質失控 | **Gate 阻斷** |

### 8.3 轉入前檢查清單

| 檢查項目 | 必須通過 |
|----------|----------|
| T002_ID 存在 | ✅ 是 |
| 標準化名稱有值 | ✅ 是 |
| 標準化品牌有值 | ✅ 是 |
| 供應商ID 有效 | ✅ 是 |
| 狀態為 READY_FOR_T005 | ✅ 是 |

---

## 九、Gate-G：T005_TRANSFERRING → LOCKED_AFTER_T005（關鍵）

### 9.1 通過條件

| 條件 | 說明 | 驗證方式 |
|------|------|----------|
| T005 已建立記錄 | T005 有對應資料 | T005_UID 有值 |
| T005_UID 已回填 | T002 持有 T005_UID | 欄位檢查 |
| 資料一致性確認 | T002 與 T005 資料相符 | 比對驗證 |

### 9.2 禁止事項

| 禁止行為 | 原因 | 後果 |
|----------|------|------|
| T005_UID 未回填即鎖定 | 關聯遺失 | **Gate 阻斷** |
| 資料不一致即鎖定 | 資料錯誤 | **Gate 阻斷** |
| 轉入失敗強制鎖定 | 資料遺失 | **Gate 阻斷** |

### 9.3 鎖定後行為

| 行為 | 說明 |
|------|------|
| 記錄唯讀 | 禁止任何修改 |
| 狀態不可逆 | 無法回到其他狀態 |
| 保留追溯 | 作為歷史記錄 |

## 十、失敗處理規則

### 10.1 Gate 失敗處理

| Gate | 失敗後狀態 | 處理方式 |
|------|------------|----------|
| Gate-A | 維持 INCOMPLETE | 重新判定責任 |
| Gate-B | 維持 WAITING_* | 繼續等待回補 |
| Gate-C | 維持 PENDING_AI_CLEAN | 等待清洗就緒 |
| Gate-D | 視情況 | INCOMPLETE 或 PENDING_HUMAN |
| Gate-E | 維持 PENDING_HUMAN_CONFIRM | 等待人工確認 |
| Gate-F | 維持 READY_FOR_T005 | 修正後重試 |
| Gate-G | 回到 READY_FOR_T005 | 重新轉入 |

### 10.2 重試規則

| 規則 | 說明 |
|------|------|
| 最大重試次數 | 3 次 |
| 重試間隔 | 遞增（1h, 4h, 24h） |
| 超過上限 | 人工介入 |
