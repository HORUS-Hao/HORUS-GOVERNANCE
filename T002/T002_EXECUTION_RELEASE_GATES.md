## 一、Purpose

本文件定義 T002 各階段的 Release Gate，用於：

- 明確 ADR-0001 解除的前置條件
- 定義 Phase 轉換的 Gate 類型與順序
- 標示「最後一道防線」

**未通過所有 Gate 前，任何程式碼皆屬違規。**

## 五、人為審核 Gate（👤）

### 5.1 RG-05：Canonical 邊界再確認

| 項目 | 說明 |
|------|------|
| Gate 名稱 | Canonical 邊界再確認 |
| 審核者 | Architect |
| 審核內容 | T002 ≠ Canonical，T005 = Canonical 邊界無變更 |
| 確認方式 | 書面簽核 |
| 通過標準 | Architect 明確確認邊界定義 |
| 若未通過 | 不得進入下一 Gate |

**確認聲明（需簽署）：**
```
我確認：
□ T002 為 Derived Layer，非 Canonical
□ T005 為唯一 Canonical Schema
□ T002 → T005 寫入永久禁止
□ 依賴方向為 T002 → T005
```

### 5.2 RG-06：AI/Agent 限制再確認

| 項目 | 說明 |
|------|------|
| Gate 名稱 | AI/Agent 限制再確認 |
| 審核者 | Architect |
| 審核內容 | Phase 1 之 AI/Agent 限制延續至 Phase 4 |
| 確認方式 | 書面簽核 |
| 通過標準 | Architect 明確確認限制延續 |
| 若未通過 | 不得進入下一 Gate |

**確認聲明（需簽署）：**
```
我確認：
□ AI/Agent 不得自動執行任何實作
□ AI/Agent 不得綁定至 Sheet/Script/Workflow
□ AI/Agent 不得產生任何副作用輸出
□ 此限制延續至另有 ADR 解除為止
```

### 5.3 RG-07：可寫入欄位白名單批准

| 項目 | 說明 |
|------|------|
| Gate 名稱 | 可寫入欄位白名單批准 |
| 審核者 | Architect |
| 審核內容 | 明確批准可人工寫入的欄位清單 |
| 確認方式 | 書面簽核 |
| 通過標準 | 白名單已定義且批准 |
| 若未通過 | 不得設計任何寫入功能 |

**白名單範圍（需批准）：**

| 欄位 | 類型 | 批准狀態 |
|------|------|----------|
| 備註 | Human-Input | ⏳ 待批准 |
| 人工確認人 | Human-Input | ⏳ 待批准 |
| 確認日期 | Human-Input | ⏳ 待批准 |

**排除範圍（永久禁止寫入）：**
- System-Owned 欄位
- AI-Generated 欄位
- Sync-Derived 欄位
- Canonical Reference 欄位

| 項目 | 說明 |
|------|------|
| Gate 名稱 | 第一實作類型確認 |

| 確認方式 | 書面指定 |
| 通過標準 | 明確指定實作類型 |
| 若未通過 | 不得開始任何實作 |

**允許的第一實作類型（僅限以下之一）：**

| 類型 | 說明 | 副作用 |
|------|------|--------|
| Read-only Validator | 資料驗證器 | 無 |
| Read-only Analyzer | 資料分析器 | 無 |
| Read-only Reporter | 報表產生器 | 無 |

**禁止作為第一實作：**
- 任何寫入功能
- 任何狀態變更功能
- 任何通知發送功能
- 任何 UI 功能
