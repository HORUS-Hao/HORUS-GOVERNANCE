# T002 缺漏資料回補治理政策

**文件類型**: Governance Policy
**狀態**: Active
**適用範圍**: T002 原料清洗系統
**生效日期**: 2026-01-13
**上位文件**: ADR-T002-COLLABORATION-PHASE1.md

---

## 一、Purpose

本文件定義 T002 缺漏資料的回補治理政策，用於：

- 判斷何時需要啟動回補
- 明確回補責任人
- 定義通知規則

本文件**僅定義規則，不涉及任何程式碼或工具**。

---

## 二、回補觸發條件

### 2.1 需要回補的情況

| 情況代碼 | 情況描述 | 觸發條件 |
|----------|----------|----------|
| GAP-001 | P0 欄位缺失 | 建檔時發現 P0 欄位為空 |
| GAP-002 | P1 欄位缺失 | 轉入 T005 前發現 P1 欄位為空 |
| GAP-003 | AI 清洗失敗 | 無法產出標準化欄位 |
| GAP-004 | 人工確認拒絕 | 確認人標記資料有問題 |
| GAP-005 | 供應商資料異常 | 原始資料格式錯誤或內容矛盾 |

### 2.2 不需要回補的情況

| 情況 | 說明 |
|------|------|
| P2 欄位缺失 | 不阻斷流程，不主動回補 |
| 信心度低但人工已確認 | 已處理完成 |
| 已轉入 T005 | 進入 T005 後由 T005 治理 |

## 三、回補責任人

### 3.1 責任判定規則

| 缺失欄位類型 | 責任方 | 判定依據 |
|--------------|--------|----------|
| 原廠商品名稱 | 供應商 | 供應商應提供完整商品名 |
| 原廠品牌 | 供應商 / 品牌方 | 視合作關係判定 |
| 原廠型號 | 供應商 / 品牌方 | 視合作關係判定 |
| 原始價格 | 供應商 | 供應商應提供報價 |
| 原始幣別 | 供應商 | 供應商應標示幣別 |
| 供應商ID | 內部 | S001 供應商庫維護者 |
| 供應商名稱 | 內部 | S001 供應商庫維護者 |
| 標準化欄位 | 內部 | 清洗規則維護者 |

### 3.2 責任方定義

| 責任方 | 定義 | 聯繫方式 |
|--------|------|----------|
| 供應商 | 提供原始商品資料之外部廠商 | 依供應商資料庫 |
| 品牌方 | 商品品牌擁有者 | 依品牌聯繫資料 |
| 內部人員 | HORUS 系統維護人員 | 依內部分工 |

### 3.3 責任判定流程

| 順序 | 判定步驟 |
|------|----------|
| 1 | 識別缺失欄位 |
| 2 | 查詢欄位來源類型（Sync-Derived / AI-Generated / Human-Input） |
| 3 | 依來源類型判定責任方 |
| 4 | 若來源為供應商，進一步判定是否為品牌方責任 |
| 5 | 記錄責任判定結果 |

## 四、通知規則

### 4.1 何時可以發送通知

| 條件 | 可否通知 | 說明 |
|------|----------|------|
| 責任方已明確判定 | 可以 | 有明確通知對象 |
| 缺失欄位為 P0 或 P1 | 可以 | 影響流程進行 |
| 首次發現缺失 | 可以 | 需告知責任方 |
| 催促（逾期未回補） | 可以 | 需設定催促間隔 |

### 4.2 何時不得發送通知

| 條件 | 禁止通知 | 說明 |
|------|----------|------|
| 責任方未判定 | 禁止 | 無明確對象 |
| P2 欄位缺失 | 禁止 | 不主動催促 |
| 已轉入 T005 | 禁止 | 脫離 T002 治理範圍 |
| 催促間隔未到 | 禁止 | 避免騷擾 |
| 已達催促上限 | 禁止 | 轉人工處理 |

### 4.3 通知類型

| 通知代碼 | 通知類型 | 對象 | 觸發條件 |
|----------|----------|------|----------|
| NOTIFY-001 | 首次缺漏通知 | 責任方 | 首次判定責任 |
| NOTIFY-002 | 催促通知 | 責任方 | 逾期未回補 |
| NOTIFY-003 | 上報通知 | 內部主管 | 達催促上限 |
| NOTIFY-004 | 回補完成確認 | 發起人 | 責任方已回補 |

### 4.4 通知為治理通知

| 聲明 | 說明 |
|------|------|
| 通知性質 | 治理通知，非系統自動行為 |
| 發送方式 | 由本政策規範，不指定工具 |
| 責任歸屬 | 依本政策判定 |

---

## 五、催促規則

### 5.1 催促時程

| 對象 | 首次通知後 | 催促間隔 | 催促上限 |
|------|------------|----------|----------|
| 供應商 | 3 工作日 | 5 工作日 | 3 次 |
| 品牌方 | 3 工作日 | 5 工作日 | 3 次 |
| 內部人員 | 1 工作日 | 2 工作日 | 5 次 |

### 5.2 達催促上限處理

| 責任方 | 處理方式 |
|--------|----------|
| 供應商 | 上報採購主管，評估供應商配合度 |
| 品牌方 | 上報品牌管理負責人 |
| 內部人員 | 上報直屬主管 |

### 5.3 特殊情況

| 情況 | 處理方式 |
|------|----------|
| 責任方無法聯繫 | 立即上報 |
| 責任方拒絕回補 | 記錄拒絕原因，上報 |
| 資料無法取得 | 評估是否放棄該商品 |

## 六、回補完成判定

### 6.1 完成條件

| 條件 | 說明 |
|------|------|
| 欄位已填入 | 缺失欄位有值 |
| 格式正確 | 符合欄位格式要求 |
| 可通過清洗 | AI 清洗可處理 |

### 6.2 回補後流程

| 步驟 | 說明 |
|------|------|
| 1 | 確認回補資料 |
| 2 | 重新進入清洗流程 |
| 3 | 狀態轉為 PENDING_AI_CLEAN |
| 4 | 發送回補完成確認通知 |
