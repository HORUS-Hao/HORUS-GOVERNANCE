## 一、Purpose

本文件回答四個關鍵問題：

1. **誰**可以下「開始實作」的決定
2. 第一行 code 允許出現在**哪裡**
3. 第一個實作類型是**什麼**
4. 哪些行為即使有 code 也視為**違規**

**本文件為未來所有 Git dispute 的最終裁判依據。**

## 二、問題一：誰可以下「開始實作」的決定

### 2.1 唯一授權者

| 聲明 | 說明 |
|------|------|
| **唯一授權者** | **Architect** |
| 無替代者 | 無任何替代或代理 |
| 無例外 | 即使緊急情況亦無例外 |

### 2.2 授權方式

| 方式 | 有效性 |
|------|--------|
| 正式書面簽核 | ✅ 有效 |
| 口頭同意 | ❌ 無效 |
| 郵件同意 | ❌ 無效（除非附正式簽核） |
| 聊天訊息同意 | ❌ 無效 |
| 默示同意 | ❌ 無效 |

### 2.3 授權前提

| 前提 | 說明 |
|------|------|
| RG-10 簽核完成 | 最終批准書已簽署 |
| 所有 Gate 通過 | RG-01 至 RG-09 全部通過 |
| 無未解問題 | 無待決事項 |

### 2.4 非授權者

| 角色 | 權限 |
|------|------|
| Developer | ❌ 不可自行決定開始 |
| PM | ❌ 不可授權開始 |
| AI/Agent | ❌ 永久禁止授權 |
| 任何自動化 | ❌ 永久禁止授權 |

## 三、問題二：第一行 code 允許出現在哪裡

### 3.1 允許位置（需 Architect 指定）

| 項目 | 需指定內容 |
|------|------------|
| Repository | 明確的 repo 名稱 |
| Branch | 明確的分支名稱 |
| Directory | 明確的目錄路徑 |
| File Pattern | 明確的檔案命名規則 |

### 3.2 建議位置結構

```
{repo}/
└── T002/
    └── {implementation-type}/
        └── {file-name}.{ext}

範例：
HORUS-PDM-System/
└── T002/
    └── validators/
        └── t002_data_validator.gs
```

### 3.3 永久禁止位置

| 禁止位置 | 原因 |
|----------|------|
| T005 相關目錄 | Canonical 邊界 |
| 任何 Sheet 內嵌腳本 | 需另立 ADR |
| 任何 Add-on 專案 | 需另立 ADR |
| 任何 Trigger 設定 | 需另立 ADR |
| Production 環境 | 需另立部署 ADR |

### 3.4 位置違規判定

| 情況 | 判定 |
|------|------|
| 未指定位置即 commit | 違規 |
| commit 到禁止位置 | 違規 |
| 未經指定的其他位置 | 違規 |

## 四、問題三：第一個實作類型是什麼

### 4.1 允許的第一實作類型

| 優先級 | 類型 | 說明 | 副作用 |
|--------|------|------|--------|
| 1 | **Read-only Validator** | 資料驗證邏輯 | 無 |
| 2 | Read-only Analyzer | 資料分析邏輯 | 無 |
| 3 | Read-only Reporter | 報表產生邏輯 | 無 |

### 4.2 Read-only Validator 定義

| 特性 | 說明 |
|------|------|
| 輸入 | T002 資料（唯讀） |
| 輸出 | 驗證結果（文字/JSON） |
| 副作用 | **無**（不修改任何資料） |
| 觸發方式 | 人工執行（非自動） |

**範例功能：**
- 檢查 P0 欄位完整性
- 檢查 P1 欄位完整性
- 驗證供應商ID 有效性
- 檢查狀態一致性

### 4.3 禁止作為第一實作

| 類型 | 禁止原因 |
|------|----------|
| 寫入功能 | 需更多 Gate |
| 狀態變更功能 | 需更多 Gate |
| 通知發送功能 | 需另立 ADR |
| UI 功能 | 需另立 ADR |
| Add-on | 需另立 ADR |
| Trigger | 需另立 ADR |
| 與 T005 互動 | Canonical 邊界 |

### 4.4 第一實作的限制

| 限制 | 說明 |
|------|------|
| 單一功能 | 一次只實作一個驗證 |
| 完整測試 | 必須有測試 |
| 程式碼審閱 | 必須經審閱 |
| 文件紀錄 | 必須有文件 |

## 五、問題四：哪些行為即使有 code 也視為違規

### 5.1 絕對違規（零容忍）

| 違規行為 | 說明 | 後果 |
|----------|------|------|
| 未經 RG-10 授權即 commit | 無授權的程式碼 | 立即回滾 |
| commit 到禁止位置 | 違反位置規則 | 立即回滾 |
| 寫入 T005 | 違反 Canonical 邊界 | 立即回滾 + 調查 |
| 自動執行功能 | 違反人工觸發規則 | 立即停用 |
| AI/Agent 產生的 commit | 違反 AI 限制 | 立即回滾 |
| 修改已鎖定記錄 | 違反 LOCKED 規則 | 立即回滾 + 調查 |

### 5.2 程序違規

| 違規行為 | 說明 | 後果 |
|----------|------|------|
| 未經審閱即 merge | 規避審閱 | 回滾 + 重審 |
| 跳過測試 | 規避測試 | 阻斷 merge |
| 未更新文件 | 規避文件要求 | 阻斷 merge |
| 超出批准範圍 | 實作超出授權 | 刪除超出部分 |

### 5.3 技術違規

| 違規行為 | 說明 | 後果 |
|----------|------|------|
| 有副作用的「Read-only」 | 名實不符 | 立即停用 |
| 隱藏的寫入邏輯 | 規避檢查 | 立即回滾 + 調查 |
| 外部 API 呼叫 | 未授權的外部互動 | 立即停用 |
| 觸發器設定 | 未授權的自動化 | 立即移除 |

### 5.4 違規判定權

| 項目 | 判定者 |
|------|--------|
| 是否違規 | Architect |
| 違規嚴重程度 | Architect |
| 處理方式 | Architect |
| 上訴 | 無（Architect 為終審） |
