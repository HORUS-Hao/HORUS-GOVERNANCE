## 2. 單一商品「有些平台要上架、有些不要」的唯一設定方式

### 2.1 Step 1：總開關（不可跳過）

**檢查**：`T005-1.商品主表 → 商品狀態`

| 商品狀態 | 結果 |
|----------|------|
| ≠ 正常銷售 | 所有平台一律不可上架，WK 填什麼都無效 |
| = 正常銷售 | 進入 Step 2 |

### 2.2 Step 2：平台層設定（唯一可操作層）

**進入**：`T002-WK-平台建檔名稱`

對「同一個商品（同一 UID）」：

| 操作 | 欄位填寫 | 結果 |
|------|----------|------|
| 要上架 | 填寫實際平台商品名稱 | ✅ isEligible = true |
| 不要上架 | 保持空白 | ❌ isEligible = false |

### 2.3 範例（同一商品）

```
UID: EXAMPLE-001
T005.商品狀態: 正常銷售

平台      建檔名稱欄位           結果
───────────────────────────────────────
MOMO      "商品A官方版"          ✅ 上架
SHOPEE    (空白)                 ❌ 不上架
PCHOME    "商品A專賣"            ✅ 上架
YAHOO     "商品A Yahoo限定"      ✅ 上架
COUPANG   (空白)                 ❌ 不上架
```

### 2.4 語義定錨

```
填名稱 = 「我明確要賣到這個平台」
不填   = 「我不要賣到這個平台」
```

## 3. 為什麼不用另外加「是否上架」欄位

### 三條鐵則（任何人質疑都用這三條回應）

| 鐵則 | 說明 |
|------|------|
| **避免雙重真實** | 如果同時有「名稱」又有「是否上架」，一定會出現矛盾 |
| **避免平台擴充時炸 Schema** | 新平台只需要「加一個建檔名稱欄位」 |
| **人類操作直覺** | 營運只要記一件事：「我填了名字，就是我要賣」 |
