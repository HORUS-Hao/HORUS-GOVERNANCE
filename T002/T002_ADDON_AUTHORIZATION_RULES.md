## 一、Purpose

本文件定義 T002 Add-on 授權規則，用於：

- 明確禁止的 Add-on 類型
- 定義需 ADR 授權的 Add-on 類型
- 規範 Read-only Add-on 的允許範圍

**本文件為未來 Add-on 開發的授權依據。**

---

## 二、授權分類總覽

### 2.1 三級授權制

| 授權等級 | 說明 | 範圍 |
|----------|------|------|
| 🔴 **永久禁止** | 任何情況皆不得開發 | 高風險功能 |
| 🟡 **需 ADR 授權** | 必須另立 ADR 並經 Architect 批准 | 中風險功能 |
| 🟢 **Read-only 允許** | 無副作用操作，仍需審閱 | 低風險功能 |

### 2.2 授權判定流程

```
新 Add-on 需求
     ↓
檢查是否「永久禁止」類型
     ↓ 是 → 🔴 拒絕，無例外
     ↓ 否
檢查是否「需 ADR」類型
     ↓ 是 → 🟡 建立 ADR，等待批准
     ↓ 否
檢查是否「Read-only」類型
     ↓ 是 → 🟢 審閱後允許
     ↓ 否
     → 🔴 預設拒絕
```

## 三、永久禁止類型（🔴 紅線）

### 3.1 禁止清單

| 類型 | 說明 | 禁止原因 |
|------|------|----------|
| T002 → T005 寫入 | 任何形式寫入 T005 | 違反 Canonical 邊界 |
| 自動狀態變更 | 無人工觸發的狀態轉換 | 規避 Gate 審核 |
| 批次自動確認 | 自動填入人工確認欄位 | 規避人工流程 |
| AI/Agent 自動執行 | 無人工監督的 AI 操作 | Phase 1 限制 |
| 自動通知發送 | 無人工觸發的通知 | 規避審核 |
| T005_UID 修改 | 任何形式修改 T005_UID | 破壞關聯 |
| 已鎖定記錄修改 | 修改 LOCKED 狀態記錄 | 違反唯讀政策 |
| 自動刪除功能 | 任何自動刪除 | 資料遺失風險 |
| 外部 API 寫入 | 向外部系統寫入 T002 資料 | 資料外洩風險 |
| Webhook 觸發器 | 外部觸發 T002 操作 | 安全風險 |

### 3.2 禁止原則

| 原則 | 說明 |
|------|------|
| 無例外 | 即使 Architect 亦不可授權 |
| 永久有效 | 不因版本或時間改變 |
| 違反後果 | 立即停用並回報 |

### 3.3 如何判定

| 判定問題 | 若「是」則禁止 |
|----------|----------------|
| 是否寫入 T005？ | 🔴 禁止 |
| 是否無人工觸發？ | 🔴 禁止 |
| 是否規避 Gate？ | 🔴 禁止 |
| 是否修改 Canonical Key？ | 🔴 禁止 |
| 是否影響已鎖定記錄？ | 🔴 禁止 |

## 四、需 ADR 授權類型（🟡 審核）

### 4.1 需授權清單

| 類型 | 說明 | 需要的 ADR |
|------|------|------------|
| 人工觸發狀態變更 | 按鈕觸發狀態轉換 | ADR-T002-STATUS-UI |
| 人工觸發通知 | 按鈕發送通知 | ADR-T002-NOTIFICATION |
| 資料匯入功能 | 批次匯入原始資料 | ADR-T002-IMPORT |
| 資料匯出功能 | 匯出 T002 資料 | ADR-T002-EXPORT |
| 人工確認 UI | 確認介面 | ADR-T002-CONFIRM-UI |
| AI 清洗啟動 | 人工觸發 AI 清洗 | ADR-T002-AI-ACTIVATION |
| 報表產生 | 產生分析報表 | ADR-T002-REPORTING |
| 儀表板 | 狀態儀表板 | ADR-T002-DASHBOARD |
| 備註編輯 | Human-Input 欄位編輯 | ADR-T002-EDIT-UI |

### 4.2 ADR 授權流程

| 步驟 | 說明 |
|------|------|
| 1 | 建立 ADR 草稿 |
| 2 | 描述功能需求與風險 |
| 3 | 確認不違反禁止清單 |
| 4 | Architect 審閱 |
| 5 | 批准後方可開發 |

### 4.3 ADR 必要內容

| 項目 | 必須包含 |
|------|----------|
| 功能描述 | 明確功能範圍 |
| 風險評估 | 潛在風險與緩解 |
| Gate 影響 | 是否影響 Gate 規則 |
| 禁止清單確認 | 確認不違反紅線 |
| 回滾計畫 | 問題時如何回滾 |

## 五、Read-only 允許類型（🟢 低風險）

### 5.1 允許清單

| 類型 | 說明 | 條件 |
|------|------|------|
| 資料查詢 | 查詢 T002 記錄 | 無副作用 |
| 狀態查看 | 查看商品狀態 | 唯讀 |
| 統計檢視 | 查看統計數據 | 唯讀 |
| 欄位完整性檢查 | 查看缺失欄位 | 唯讀 |
| 歷史記錄查看 | 查看變更歷史 | 唯讀 |
| 格式驗證 | 驗證資料格式 | 不修改 |

### 5.2 允許條件

| 條件 | 說明 |
|------|------|
| 無副作用 | 不修改任何資料 |
| 無外部呼叫 | 不呼叫外部 API |
| 無通知發送 | 不發送任何通知 |
| 無狀態變更 | 不改變任何狀態 |

### 5.3 審閱要求

| 要求 | 說明 |
|------|------|
| 程式碼審閱 | 確認無副作用 |
| 測試驗證 | 確認唯讀行為 |
| 文件記錄 | 記錄功能範圍 |

## 六、特殊情況處理

### 6.1 邊界情況

| 情況 | 處理方式 |
|------|----------|
| 功能橫跨多類型 | 以最高風險類型為準 |
| 類型不明確 | 預設為「需 ADR」 |
| 新類型出現 | Architect 裁定 |

### 6.2 升級規則

| 原類型 | 可升級至 | 條件 |
|--------|----------|------|
| 🟢 Read-only | 🟡 需 ADR | 發現副作用 |
| 🟡 需 ADR | 🔴 永久禁止 | 發現違反紅線 |

### 6.3 降級規則

| 規則 | 說明 |
|------|------|
| 🔴 永久禁止 | **不可降級** |
| 🟡 需 ADR | 不可自行降級為 🟢 |
