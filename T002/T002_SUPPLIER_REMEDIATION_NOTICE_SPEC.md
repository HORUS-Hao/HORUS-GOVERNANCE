## 一、Purpose

本文件定義供應商缺漏回補通知的規格，用於：

- 規範通知內容結構
- 明確通知發送條件
- 作為未來通知系統設計的參考

**本文件不授權任何通知發送行為。**

---

## 二、通知類型定義

### 2.1 通知類型清單

| 通知代碼 | 通知名稱 | 觸發時機 | 對象 |
|----------|----------|----------|------|
| NOTICE-SUP-001 | 首次缺漏通知 | 責任判定完成 | 供應商 |
| NOTICE-SUP-002 | 第一次催促 | 首次通知後 3 工作日 | 供應商 |
| NOTICE-SUP-003 | 第二次催促 | 第一次催促後 5 工作日 | 供應商 |
| NOTICE-SUP-004 | 最終催促 | 第二次催促後 5 工作日 | 供應商 |
| NOTICE-SUP-005 | 上報通知 | 最終催促後仍未回補 | 內部主管 |
| NOTICE-SUP-006 | 回補完成確認 | 供應商回補完成 | 發起人 |

### 2.2 通知優先級

| 優先級 | 適用情況 | 處理時效 |
|--------|----------|----------|
| 高 | P0 欄位缺失 | 即時發送 |
| 中 | P1 欄位缺失 | 當日發送 |
| 低 | 催促通知 | 依排程發送 |

## 三、通知內容規格

### 3.1 首次缺漏通知 (NOTICE-SUP-001)

#### 郵件主旨
```
[HORUS] 商品資料補件通知 - {商品名稱} ({T002_ID})
```

#### 郵件內容結構
```
收件人：{供應商聯繫人}
副本：{內部採購負責人}

主旨：商品資料補件通知

{供應商名稱} 您好，

我們在處理您提供的商品資料時，發現以下欄位資料缺失，
煩請協助補齊，以利後續作業進行。

【商品資訊】
- 商品名稱：{原廠商品名稱}
- 內部編號：{T002_ID}
- 供應商：{供應商名稱}

【缺失欄位】
| 欄位名稱 | 重要性 | 說明 |
|----------|--------|------|
| {欄位1} | {P0/P1} | {欄位說明} |
| {欄位2} | {P0/P1} | {欄位說明} |

【回補方式】
請於 {截止日期} 前，以下列方式之一回覆：
1. 直接回覆本郵件，附上補齊資料
2. 聯繫您的採購窗口：{採購負責人}

如有任何疑問，請隨時與我們聯繫。

此致
{發送人姓名}
{發送人部門}
{發送日期}

---
本通知由 HORUS 系統產生
請勿直接回覆系統郵件，請回覆給 {採購負責人郵件}
```

### 3.2 催促通知 (NOTICE-SUP-002/003/004)

#### 郵件主旨
```
[HORUS][第{N}次提醒] 商品資料補件通知 - {商品名稱} ({T002_ID})
```

#### 郵件內容結構
```
收件人：{供應商聯繫人}
副本：{內部採購負責人}, {主管}（第三次起）

主旨：商品資料補件提醒（第 {N} 次）

{供應商名稱} 您好，

這是關於商品資料補件的第 {N} 次提醒。

我們於 {首次通知日期} 發送的補件通知尚未收到回覆，
煩請儘速處理，以免影響後續合作作業。

【原始通知摘要】
- 商品名稱：{原廠商品名稱}
- 缺失欄位：{欄位清單}
- 首次通知日期：{首次通知日期}
- 本次為第 {N} 次提醒

【請注意】
若於 {最終截止日期} 前仍未回覆，
將依公司流程進行後續處理。

如有任何疑問，請隨時與我們聯繫。

此致
{發送人姓名}
{發送人部門}
{發送日期}
```

### 3.3 上報通知 (NOTICE-SUP-005)

#### 郵件主旨
```
[HORUS][需處理] 供應商未回應補件通知 - {供應商名稱}
```

#### 郵件內容結構
```
收件人：{採購主管}
副本：{相關人員}

主旨：供應商補件通知逾期未回應

主管您好，

以下供應商的補件通知已達催促上限，仍未收到回覆，
請協助評估後續處理方式。

【供應商資訊】
- 供應商名稱：{供應商名稱}
- 供應商ID：{供應商ID}
- 聯繫人：{聯繫人}

【未回應商品清單】
| T002_ID | 商品名稱 | 缺失欄位 | 首次通知 | 催促次數 |
|---------|----------|----------|----------|----------|
| {ID} | {名稱} | {欄位} | {日期} | 3 |

【建議處理方式】
1. 電話聯繫供應商確認原因
2. 評估該供應商配合度
3. 考慮是否放棄該批商品

請協助處理，謝謝。

{發送人姓名}
{發送日期}
```

### 3.4 回補完成確認 (NOTICE-SUP-006)

#### 郵件主旨
```
[HORUS][已完成] 商品資料補件完成 - {商品名稱} ({T002_ID})
```

#### 郵件內容結構
```
收件人：{補件發起人}
副本：{採購負責人}

主旨：商品資料補件已完成

您好，

以下商品的資料補件已完成，資料將重新進入清洗流程。

【商品資訊】
- 商品名稱：{原廠商品名稱}
- 內部編號：{T002_ID}
- 供應商：{供應商名稱}

【補件詳情】
| 欄位名稱 | 補件前 | 補件後 |
|----------|--------|--------|
| {欄位} | {空白} | {新值} |

【後續狀態】
- 新狀態：PENDING_AI_CLEAN
- 預計處理：自動進入清洗流程

感謝您的處理。

{系統自動通知}
{發送日期}
```

## 四、通知發送規則

### 4.1 發送時機

| 通知類型 | 發送時機 | 發送條件 |
|----------|----------|----------|
| 首次通知 | 責任判定完成時 | P0 或 P1 欄位缺失 |
| 催促通知 | 依排程 | 前次通知後逾期 |
| 上報通知 | 催促達上限 | 3 次催促後仍未回應 |
| 完成確認 | 回補完成時 | 資料已補齊 |

### 4.2 發送限制

| 限制項目 | 規則 |
|----------|------|
| 每日發送上限 | 同一供應商每日最多 1 封催促 |
| 週末發送 | 禁止（順延至週一） |
| 假日發送 | 禁止（順延至工作日） |
| 重複發送 | 禁止（需等待間隔期滿） |

### 4.3 例外處理

| 例外情況 | 處理方式 |
|----------|----------|
| 供應商無聯繫方式 | 立即上報 |
| 郵件退信 | 通知採購更新聯繫方式 |
| 供應商回覆拒絕 | 記錄原因並上報 |
