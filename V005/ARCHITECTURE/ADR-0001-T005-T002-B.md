# ADR-0001｜T005 × T002 治理決策（B 階段）

Status: **ACTIVE**
Phase: **B (Governance Only)**
Effective Date: 2026-01-01
Owner: Architect

> 本文件為 MCP 的權威 Decision Record。
> 在 B 階段，任何 MCP / T005 技術行為皆不得凌駕於本決策之上。

---

## Context

T005（商品管理系統）已成為 HORUS-PDM 的 de-facto Canonical Schema，但尚未正式 Registry 化。目前 schema / data / 人工操作仍混在同一張 Sheet。

MCP 技術骨架已存在於 `C:\dev\HORUS\MCP`，但在缺乏正式 Decision Record 的情況下，任何技術連線都是「順序錯誤」。

---

## Decision

### 1. T005 定位

- T005 是 **Canonical Schema**（事實）
- T005 目前 **不是** 正式 Schema Registry
- Schema 與 Data 尚未分離

### 2. MCP 定位

- MCP = **Decision Sink**（決策落點器）
- MCP 的第一個資產是「決策內容」，不是「連線能力」
- 在內容出現前，所有技術行為都是空轉

### 3. 目前階段：B（Governance Only）

| 允許 | 禁止 |
|------|------|
| 持有治理狀態資訊 | 讀取 T005 Sheet 資料 |
| 記錄已拍板決策 | 改欄位、加欄位 |
| 作為 RUL 的 state 來源 | 同步表頭 |
| | 介入實際資料流程 |
| | 取代人工決策 |

### 4. MCP 可持有的資訊類型

- T005 是 Canonical（事實）
- 目前策略是 B（最小整理），非 C（完整重構）
- Schema 尚未 Registry 化
- 表頭同步策略決策
- 已拍板的架構決策

這些是 **decision / state**，不是 row / column / value。

## Constraints

### 禁止事項（B 階段）

1. **不啟動 MCP Server**
2. **不填 MCP Server URL**
3. **不設定 OAuth / SSE**
4. **不寫 RUL / Skill**
5. **不讓 MCP 讀寫 T005**
6. **不因「已可技術連線」而推進**

### 行為規則

任何人（包含 AI Agent）提議上述事項時：
- 不回憶討論過程
- 不推理「為什麼」
- 直接回查本 ADR

---

## Phase Transition Criteria

進入 C 階段的必要條件：

1. T005 schema 與 data 分離
2. Schema 有版本化與 diff
3. 有明確的變更審核流程
4. Architect 明確批准

在上述條件滿足前，維持 B 階段。

---

## Consequences

### Positive

- MCP 的「記憶」從人類腦袋轉移到 repo 結構
- 開發者/AI Agent 即使語意跑掉，也能被拉回
- 未來進入 C 階段時，有清楚的起點

### Negative

- 短期內 MCP 無法發揮技術能力
- 需要人工維護 ADR

### Neutral

- 技術骨架保留，不浪費先前工作
