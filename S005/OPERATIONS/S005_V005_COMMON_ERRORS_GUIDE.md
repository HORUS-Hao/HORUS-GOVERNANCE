# S005 / V005 常見問題判斷指南

**文件版本**: v1.0
**適用版本**: S005 / V005 v2.3 FREEZE
**建立日期**: 2026-01-12
**文件性質**: 系統管理者問題排查手冊

---

## 一、文件目的

本文件提供 S005 / V005 系統常見問題的判斷流程。
系統管理者應依據本文件判斷問題性質，避免將設定問題誤報為系統錯誤。

---

## 二、問題分類

| 分類 | 說明 | 處理方式 |
|------|------|----------|
| 設定問題 | 治理資料未設定或設定錯誤 | 管理者自行補齊設定 |
| 使用問題 | 操作流程不正確 | 參照操作手冊 |
| 系統錯誤 | 程式異常或服務中斷 | 聯繫系統開發者 |

## 三、高優先問題判斷

### 3.1 問題：外部使用者已提交，但管理者未收到任何審核 Mail

**問題描述**：
外部使用者成功建立並提交報價單，但公司管理者沒有收到任何通知郵件。

**判斷流程**：

```
步驟 1：檢查 Company_Profile.supervisor_emails
        │
        ├─ 欄位為空 → 行為正常（治理資料未設定）
        │              → 解法：補齊 supervisor_emails 設定
        │
        └─ 欄位有值 → 繼續步驟 2

步驟 2：檢查 Email 地址是否正確
        │
        ├─ 有拼寫錯誤 → 修正 Email 地址
        │
        └─ 地址正確 → 繼續步驟 3

步驟 3：檢查郵件是否進入垃圾郵件匣
        │
        ├─ 在垃圾郵件匣 → 將寄件者加入白名單
        │
        └─ 不在垃圾郵件匣 → 聯繫系統開發者
```

**結論**：

| 情況 | 性質 | 處理方式 |
|------|------|----------|
| supervisor_emails 為空 | 設定問題 | 管理者補齊設定 |
| Email 地址錯誤 | 設定問題 | 管理者修正設定 |
| 郵件進垃圾郵件 | 使用問題 | 使用者調整郵件設定 |
| 以上皆非 | 可能為系統錯誤 | 聯繫開發者 |

**重要聲明**：
- 若 `supervisor_emails` 為空，系統不發送郵件是**正常行為**
- 此情況**不屬於系統錯誤**
- **不需要工程處理**
- 補齊設定後，後續的報價單通知將正常發送
- 已錯過的郵件**不會補發**

### 3.2 問題：外部使用者無法登入

**問題描述**：
外部使用者嘗試登入系統，但畫面顯示「無法取得登入資訊」。

**判斷流程**：

```
步驟 1：確認使用者是否使用無痕模式
        │
        ├─ 是 → 請使用者改用一般瀏覽器模式
        │
        └─ 否 → 繼續步驟 2

步驟 2：確認 Web App 部署設定
        │
        ├─ Execution Identity = Owner → 外部帳號無法取得 Email
        │                              → 需修正部署設定（開發者處理）
        │
        └─ Execution Identity = User → 繼續步驟 3

步驟 3：確認 Admin_Users 是否有該使用者
        │
        ├─ 沒有 → 管理者新增使用者
        │
        └─ 有 → 繼續步驟 4

步驟 4：確認使用者 status 是否為 active
        │
        ├─ 不是 → 管理者修改狀態
        │
        └─ 是 → 聯繫系統開發者
```

---

### 3.3 問題：使用者無法選擇某個公司

**問題描述**：
使用者登入後，公司下拉選單沒有顯示預期的公司。

**判斷流程**：

```
步驟 1：檢查 User_Company_Permission
        │
        ├─ 沒有該使用者 + 公司的記錄 → 管理者新增授權
        │
        └─ 有記錄 → 繼續步驟 2

步驟 2：檢查 company_code 是否正確
        │
        ├─ 與 Company_Profile 不符 → 管理者修正 company_code
        │
        └─ 正確 → 聯繫系統開發者
```

---

### 3.4 問題：報價單無法審核

**問題描述**：
使用者嘗試核准或退回報價單，但操作失敗。

**判斷流程**：

```
步驟 1：確認使用者身分
        │
        ├─ 外部使用者 → 外部使用者無法審核（設計如此）
        │
        └─ 內部使用者 → 繼續步驟 2

步驟 2：確認使用者是否為 FINAL_APPROVERS
        │
        ├─ 不是 → 該使用者沒有審核權限
        │
        └─ 是 → 聯繫系統開發者
```

**備註**：v2.3 FREEZE 的 FINAL_APPROVERS 為程式碼常數，無法透過 Sheet 設定修改。

## 四、一般問題判斷

### 4.1 問題：OTP 驗證碼沒收到

**判斷流程**：
1. 檢查郵件是否進入垃圾郵件匣
2. 確認 Email 地址拼寫正確
3. 等待 1-2 分鐘（郵件可能延遲）
4. 點擊「重新發送 OTP」
5. 若仍未收到，聯繫系統開發者

### 4.2 問題：PIN 碼輸入錯誤太多次被鎖定

**說明**：
連續輸入錯誤 PIN 碼超過 5 次，帳號將被鎖定 15 分鐘。

**處理方式**：
- 等待 15 分鐘後重試
- 或請管理者清除 `Admin_Users.locked_until` 欄位

### 4.3 問題：報價單顯示金額錯誤

**判斷流程**：
1. 確認商品數量和單價是否正確輸入
2. 確認是否有未預期的折扣或加價
3. 若輸入正確但計算錯誤，聯繫系統開發者

## 五、問題回報格式

若需聯繫系統開發者，請提供以下資訊：

| 項目 | 說明 |
|------|------|
| 問題描述 | 簡述發生什麼問題 |
| 重現步驟 | 如何重現此問題 |
| 使用者 Email | 發生問題的使用者 |
| 報價單編號 | 若與特定報價單相關 |
| Console 錯誤 | 瀏覽器 Console 的錯誤訊息（如有） |
| 截圖 | 問題畫面截圖（如有） |
