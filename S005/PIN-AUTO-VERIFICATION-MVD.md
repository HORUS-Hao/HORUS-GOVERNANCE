# PIN 自動驗證最小可行定義（MVD）

- 文件：PIN-AUTO-VERIFICATION-MVD.md
- 版本：v1.0.0
- 建立日期：2026-01-08
- 狀態：**定義文件（不執行）**
- 範圍：**僅限 pin_tmp / pin_hash**

---

## 總裁定

> **本任務僅解決 PIN 正確性是否可被自動判斷，**
> **不解決放行、不解決權限、不解決責任歸屬。**

---

## 一、pin_tmp 的生命週期

### 1.1 完整週期

```
產生 → 使用 → 失效
```

| 階段 | 時機 | 操作者 | 位置 | 說明 |
|------|------|--------|------|------|
| **產生** | 新建使用者時 | 管理者（人工） | Admin_Users.pin_tmp (F欄) | 手動輸入明文 PIN |
| **使用** | 產生 hash 時 | 管理者（人工） | =PIN_HASH(F2) 公式 | 轉換為 SHA-256 hash |
| **失效** | 產生 hash 後 | 管理者（人工） | 清空 F 欄 | **必須立即清空** |

### 1.2 生命週期特性

| 特性 | 說明 |
|------|------|
| 存在時間 | 極短（僅限 hash 產生過程） |
| 系統讀取 | ❌ **禁止**（程式碼不存取此欄位） |
| 寫入主體 | 人工（管理者） |
| 清空責任 | 人工（管理者） |
| 失效條件 | 人工清空（無自動機制） |

### 1.3 pin_tmp 與自動化的關係

| 問題 | 結論 |
|------|------|
| pin_tmp 是否可自動驗證？ | ❌ **否**（系統不讀取此欄位） |
| pin_tmp 是否需要自動化？ | ❌ **否**（僅為 hash 產生的暫存，不應自動化） |
| pin_tmp 對自動驗證的影響 | **無**（與 runtime 驗證無關） |

## 二、pin_hash 的角色定位

### 2.1 核心定位

> **pin_hash 是「驗證憑證」，不是「權限」。**

| 屬性 | 說明 |
|------|------|
| 儲存位置 | Admin_Users.pin_hash (C欄) |
| 資料型態 | SHA-256 hash（64 字元 hex） |
| 產生方式 | =PIN_HASH(pin_tmp) 或 sha256_(pin) |
| 系統讀取 | ✅ **是**（唯一權威來源） |
| 寫入主體 | 人工建立 / 系統更新（PIN 變更時） |

### 2.2 pin_hash 的用途

| 用途 | 函數 | 說明 |
|------|------|------|
| **登入驗證** | `loginWithPin()` | 比對 `sha256_(pin) === user.pin_hash` |
| **PIN 變更驗證** | `requestPinChange()` | 比對舊 PIN hash |
| **Session 建立** | `createDeviceSession_()` | 記錄 `last_pin_hash` |
| **PIN 變更偵測** | `detectLoginRiskEvent_()` | 比對 `session.last_pin_hash !== currentPinHash` |

### 2.3 pin_hash 不是權限

| 概念 | pin_hash | Role/Permission |
|------|----------|-----------------|
| 決定「是誰」 | ✅ 身份驗證 | ❌ |
| 決定「能做什麼」 | ❌ | ✅ 權限控制 |
| 影響流程放行 | ❌ **否** | ✅ 是 |
| 影響狀態轉換 | ❌ **否** | ✅ 是 |

**關鍵論述**：
- PIN 驗證成功 ≠ 獲得任何權限
- PIN 驗證成功 = 確認身份（Authentication）
- 權限（Authorization）由 USERS_ACCESS.role 決定

## 三、「不需人工」的明確條件

### 3.1 完全不需人工判斷的情境

| 情境 | 判斷邏輯 | 人工介入 |
|------|----------|----------|
| **PIN 正確性** | `sha256_(inputPin) === user.pin_hash` | ❌ 不需要 |
| **PIN 錯誤計數** | `failed_attempts >= 5` → 鎖定 | ❌ 不需要 |
| **PIN 變更偵測** | `currentPinHash !== session.last_pin_hash` | ❌ 不需要 |
| **Session 有效性** | `expire_at > now && !revoked` | ❌ 不需要 |

### 3.2 自動判斷的數學特性

| 特性 | 說明 |
|------|------|
| **確定性** | hash 比對結果是 true/false，無灰色地帶 |
| **可重複性** | 相同輸入永遠產生相同結果 |
| **無需解讀** | 不需理解 PIN 內容，只需比對 hash |
| **無需授權** | 比對操作不需要任何權限決策 |

### 3.3 自動判斷條件清單

```
✅ 可完全自動判斷：
1. PIN 是否正確（hash 比對）
2. PIN 是否已變更（與 Session 記錄比對）
3. 登入失敗次數是否達到閾值
4. 帳號是否處於鎖定狀態
5. Session 是否有效/過期
```

## 四、「仍需人工」的明確條件

### 4.1 必須人工介入的情境

| 情境 | 原因 | 人工角色 |
|------|------|----------|
| **新建使用者** | 需要設定初始 PIN | 管理者 |
| **PIN 交付** | 系統不寄送 PIN | 管理者 → 使用者 |
| **手動解鎖帳號** | 非正常解鎖需人工判斷 | 管理者 |
| **PIN 重設（忘記）** | 需驗證使用者身份 | 管理者 |
| **清空 pin_tmp** | 安全規範要求 | 管理者 |

### 4.2 人工介入的原因

| 原因類別 | 說明 |
|----------|------|
| **安全性** | PIN 明文不應透過系統傳遞 |
| **責任歸屬** | 人工操作有明確責任人 |
| **例外處理** | 異常情況需人工判斷 |
| **稽核要求** | 某些操作需留下人工決策記錄 |

### 4.3 人工介入條件清單

```
❌ 仍需人工判斷：
1. 初始 PIN 設定
2. PIN 交付給使用者
3. 管理者強制解鎖帳號
4. 使用者忘記 PIN 的處理
5. pin_tmp 欄位的清空
6. 例外授權（如跳過 OTP）
```

## 五、為何不影響 Authority 的論證

### 5.1 Authority 定義（引用 S005-AUTHORITY-MCD.md）

| Authority 要件 | 與 PIN 的關係 |
|----------------|---------------|
| User 身分唯一可追蹤 | PIN 是身份驗證手段之一，不是唯一性來源 |
| Company 關聯明確 | PIN 與 Company 無關 |
| Role 影響行為 | PIN 不影響 Role |
| State 不可逆 | PIN 不影響狀態機 |
| Approval 責任歸屬 | PIN 不影響 Approval |

### 5.2 PIN 自動驗證不影響 Authority 的原因

| 論點 | 說明 |
|------|------|
| **不改變權限結構** | pin_hash 比對不會修改 USERS_ACCESS.role |
| **不影響狀態轉換** | PIN 驗證結果不會改變 QUOTE_STATUS |
| **不改變責任歸屬** | approved_by 仍由 Approver 決定，非 PIN 決定 |
| **不改變審批流程** | Approval Token 機制不受 PIN 驗證影響 |
| **不擴展權限範圍** | PIN 正確不代表可執行任何額外操作 |

### 5.3 隔離證明

```
PIN 驗證 (Authentication) ─────────┐
                                   │
                                   ├── 獨立層級
                                   │
Authority (Authorization) ─────────┘

PIN 驗證成功 ≠ Authority 變更
PIN 驗證失敗 ≠ Authority 變更
```

### 5.4 影響範圍比較

| 操作 | 影響 Authority | 影響 PIN 驗證 |
|------|----------------|---------------|
| 修改 USERS_ACCESS.role | ✅ | ❌ |
| 修改 QUOTE_STATUS | ✅ | ❌ |
| 修改 approved_by | ✅ | ❌ |
| 修改 pin_hash | ❌ | ✅ |
| hash 比對 | ❌ | ✅ |

## 六、結論

### 6.1 自動驗證可行性

| 項目 | 結論 |
|------|------|
| PIN 正確性可自動判斷 | ✅ **是** |
| 需要人工決定正確性 | ❌ **否** |
| 需要人工決定放行 | **不在本任務範圍** |

### 6.2 最終裁定

> **PIN 正確性驗證可以完全自動化，因為：**
> 1. hash 比對是確定性操作
> 2. 不需要理解 PIN 內容
> 3. 不涉及任何權限決策
> 4. 不影響 Authority 結構
