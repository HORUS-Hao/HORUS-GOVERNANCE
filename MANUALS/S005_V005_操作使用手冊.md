## 0. 權限機制技術說明（系統管理員參考）

本節說明系統權限的**實際運作機制**，供系統管理員理解與設定參考。

### 0.1 身分判斷機制

| 判斷方式 | 實作 |
|----------|------|
| Internal / External 判斷 | **Hard Code Domain**（程式碼內建） |
| 判斷函數 | `isInternalUser_(email)` |
| Internal 網域 | `@horus.tw`, `@dapanda.com.tw` |
| External | 其他所有網域 |

**重要**：Internal / External 判斷**不查詢任何資料表**，純粹依據 Email Domain 決定。

### 0.2 權限資料表用途

| 資料表 | 用途 | 生效時機 |
|--------|------|----------|
| **User_Company_Permission** | 決定使用者可代表哪些公司建立報價 | 建立報價時（公司選單） |
| **USERS_ACCESS** | 角色權限控制 | V005 審核時 |
| **Admin_Users** | 登入驗證（Email + PIN） | 登入時 |
| **Admin_Sessions** | OTP Session 管理 | OTP 驗證時 |
| **Company_Profile** | 公司資料、印章（`stamp_file_id`） | 報價 / 核准時 |

### 0.2a 印章治理說明

> **印章以 Google Drive File ID 綁定，重新命名或移動檔案不影響系統。**

| 項目 | 說明 |
|------|------|
| 系統識別方式 | `Stamp_Registry.stamp_file_id`（Drive File ID） |
| 檔名 | 無系統意義，可任意命名 |
| 資料夾位置 | 無系統意義，可任意移動 |
| 變更印章 | 更新 `Stamp_Registry` 表的 `stamp_file_id` 欄位 |

### 0.2b Stamp_Registry（v0 新增）

**v0 狀態**：僅支援公司章

| 項目 | 說明 |
|------|------|
| Runtime 來源 | `Stamp_Registry` 表（唯一權威） |
| 支援類型 | COMPANY（公司章）✅ / PERSONAL（個人章）⏸ |
| 個人章限制 | 僅 Internal User 可用，External 禁止 |
| UI 切換 | v0 不提供，固定使用公司章 |

**未來升級點**：
- Snapshot 記錄使用的 stamp_id
- UI 提供印章選擇（Internal only）

### 0.3 審核權限判斷

```
審核操作（核准/駁回）
    │
    ├─ Step 1: isInternalUser_(email) ← Hard Code Domain 判斷
    │   └─ [External] → 403 EXTERNAL_FORBIDDEN（Hard Gate，不查表）
    │
    └─ [Internal]
        └─ Step 2: checkApproverPermission_()
            └─ USERS_ACCESS.role === 'APPROVER' → 允許
            └─ 其他 → 拒絕
```

### 0.4 目前未生效的設計（預留欄位）

以下設計存在於系統中，但**目前未實際執行任何權限檢查**：

| 項目 | 狀態 | 說明 |
|------|------|------|
| `User_Company_Permission.role` | 欄位存在，讀取但未使用 | 預留欄位，目前不影響任何邏輯 |
| `USERS_ACCESS.role = 'VIEWER'` | 定義存在，未檢查 | 目前無對應權限控制 |
| `USERS_ACCESS.role = 'CREATOR'` | 定義存在，未檢查 | 目前無對應權限控制 |
| `USERS_ACCESS.role = 'ISSUER'` | 定義存在，未檢查 | 目前無對應權限控制 |

**注意**：目前唯一生效的角色是 `APPROVER`，其他角色設定不會產生任何效果。

## 2. 系統角色總覽

系統區分兩種使用者身分：**Internal（內部）** 與 **External（外部）**。

### 2.1 Internal 使用者（內部人員）

| 項目 | 說明 |
|------|------|
| 定義 | Email 網域為 `@horus.tw` 或 `@dapanda.com.tw` |
| 可做的事 | 建立報價單、檢視報價單、審核報價單（核准/駁回） |
| 登入方式 | PIN 碼 + OTP 驗證（新裝置時） |

### 2.2 External 使用者（外部人員）

| 項目 | 說明 |
|------|------|
| 定義 | Email 網域非 `@horus.tw` 且非 `@dapanda.com.tw` |
| 可做的事 | 建立報價單、檢視報價單 |
| 永遠不能做的事 | 審核報價單（核准/駁回）—— 系統會強制阻擋 |
| 登入方式 | PIN 碼 + OTP 驗證（每次登入皆需） |

### 2.3 簡單判斷方式

- 你的 Email 是 `xxx@horus.tw` → 你是 Internal
- 你的 Email 是 `xxx@dapanda.com.tw` → 你是 Internal
- 你的 Email 是其他網域（如 `xxx@gmail.com`）→ 你是 External

## 3. 登入與身分驗證流程

### 3.1 Internal 使用者登入流程

1. 開啟 S005 報價單系統網址
2. 輸入你的公司 Email（如 `yourname@horus.tw`）
3. 輸入你的 6 位數 PIN 碼
4. 點擊「登入」
5. **首次使用新裝置時**：
   - 系統會寄送 OTP 驗證碼到你的 Email
   - 輸入 6 位數 OTP 驗證碼
   - 點擊「驗證」
6. 登入成功，進入報價單填寫畫面

### 3.2 External 使用者登入流程

1. 開啟 S005 報價單系統網址
2. 輸入你的 Email
3. 輸入你的 6 位數 PIN 碼
4. 點擊「登入」
5. **每次登入都需要 OTP 驗證**：
   - 系統會寄送 OTP 驗證碼到你的 Email
   - 輸入 6 位數 OTP 驗證碼
   - 點擊「驗證」
6. 登入成功，進入報價單填寫畫面

### 3.3 登入常見問題

| 問題 | 原因 | 解決方式 |
|------|------|----------|
| PIN 碼錯誤 | 輸入錯誤超過 5 次 | 等待 15 分鐘後重試 |
| 收不到 OTP | Email 地址錯誤或郵件延遲 | 檢查垃圾郵件，或點擊「重新寄送」 |
| 帳號不存在 | 尚未被加入系統 | 聯繫系統管理員申請帳號 |

## 4. 報價單操作流程（S005）

S005 是報價單填寫工具，用於建立新的報價單。

### 4.1 可以做的事

#### 4.1.1 建立報價單

1. 登入系統後，會看到報價單填寫畫面
2. 填寫報價方資訊：
   - 報價日期（自動帶入今天）
   - 報價公司（從下拉選單選擇你被授權的公司）
3. 填寫報價對象資訊：
   - 客戶公司名稱
   - 聯絡人姓名
   - 職稱
   - Email
4. 填寫商品項目：
   - 點擊「+ 新增清單項目」新增商品列
   - 填入圖片網址、型號、商品名稱、數量、單價
   - 系統會自動計算小計與總計
5. 確認所有資訊無誤後，點擊「確認遞交報價」
6. 系統顯示成功訊息，報價單建立完成

#### 4.1.2 選擇歷史客戶

- 在「快速選取」下拉選單中，可以選擇之前報價過的客戶
- 選擇後會自動帶入客戶資訊

#### 4.1.3 查看已建立的報價單

- 報價單建立成功後，會顯示「查看報價單」按鈕
- 點擊後會開啟 V005 報價單檢視器

### 4.2 不能做的事

| 禁止事項 | 說明 |
|----------|------|
| 選擇未授權的公司 | 下拉選單只會顯示你被授權的公司 |
| 修改已遞交的報價單 | 報價單遞交後無法修改，需建立新單 |
| 刪除報價單 | 使用者無法刪除報價單 |

## 5. 報價單檢視與審核流程（V005）

V005 是報價單檢視器，用於查看報價單內容與進行審核。

### 5.1 Internal 使用者

#### 5.1.1 可以做的事

**檢視報價單**
- 開啟 V005 連結後，會顯示報價單完整內容
- 包含：報價方資訊、客戶資訊、商品明細、金額總計

**審核報價單**
- 畫面上方會顯示審核工具列
- 可以執行以下操作：
  - **核准**：點擊「核准」按鈕，報價單狀態變更為「已核准」
  - **駁回**：點擊「駁回」按鈕，輸入駁回原因，報價單狀態變更為「已駁回」

**下載與分享**
- 可下載報價單 PDF
- 可預覽報價單

#### 5.1.2 審核流程步驟

1. 從 Email 通知或系統連結開啟報價單
2. 檢視報價單內容是否正確
3. 確認無誤後：
   - 點擊「核准」→ 確認 → 完成
4. 如需修改：
   - 點擊「駁回」→ 輸入駁回原因 → 確認 → 完成

### 5.2 External 使用者

#### 5.2.1 可以做的事

**檢視報價單**
- 開啟 V005 連結後，會顯示報價單完整內容
- 可以查看所有報價資訊

**下載與分享**
- 可下載報價單 PDF
- 可預覽報價單

#### 5.2.2 永遠不能做的事

| 禁止事項 | 系統行為 |
|----------|----------|
| 核准報價單 | 系統不會顯示核准按鈕 |
| 駁回報價單 | 系統不會顯示駁回按鈕 |
| 任何審核操作 | 即使嘗試透過其他方式，系統也會強制拒絕 |

**重要說明**：

- External 使用者**永遠**無法執行審核操作
- 這是系統的安全設計，無法透過任何方式繞過
- 如果你是 External 使用者且需要審核功能，請聯繫系統管理員討論

## 6. 常見錯誤與系統行為說明

### 6.1 為什麼看不到審核按鈕？

| 可能原因 | 說明 |
|----------|------|
| 你是 External 使用者 | External 使用者永遠看不到審核按鈕，這是正常行為 |
| 報價單狀態已結案 | 已核准或已駁回的報價單不會顯示審核按鈕 |
| 你沒有該公司的審核權限 | 請確認你是否有該報價公司的審核權限 |

### 6.2 為什麼會出現 403 錯誤？

403 錯誤表示「權限不足」，常見原因：

| 錯誤訊息 | 原因 | 解決方式 |
|----------|------|----------|
| EXTERNAL_FORBIDDEN | External 使用者嘗試審核 | 這是正常阻擋，External 使用者無法審核 |
| OTP_REQUIRED | 未完成 OTP 驗證 | 重新登入並完成 OTP 驗證 |
| COMPANY_NOT_ALLOWED | 無該公司存取權限 | 聯繫系統管理員確認權限 |
| 權限不足 | 帳號權限不足 | 聯繫系統管理員確認角色設定 |

### 6.3 其他常見問題

| 問題 | 原因 | 解決方式 |
|------|------|----------|
| 報價公司選單是空的 | 帳號未被授權任何公司 | 聯繫系統管理員設定權限 |
| 登入後畫面空白 | 瀏覽器快取問題 | 清除瀏覽器快取後重試 |
| OTP 驗證碼過期 | 驗證碼有效期限 5 分鐘 | 點擊「重新寄送」取得新驗證碼 |

## 7. 操作安全提醒

### 7.1 關於 External 使用者限制

系統對 External 使用者設有嚴格的安全限制：

| 限制項目 | 說明 |
|----------|------|
| 審核功能 | External 使用者永遠無法執行審核操作 |
| 伺服器端檢查 | 即使畫面顯示按鈕，伺服器也會拒絕執行 |
| 無法繞過 | 這是系統設計的安全機制，無法透過任何方式繞過 |

### 7.2 帳號安全提醒

- **PIN 碼保密**：不要將 PIN 碼告訴他人
- **OTP 保密**：OTP 驗證碼僅供本人使用
- **登出習慣**：使用完畢請點擊「登出」
- **共用電腦**：在共用電腦上使用後，請務必登出並關閉瀏覽器

### 7.3 操作注意事項

- 報價單遞交前請仔細檢查內容，遞交後無法修改
- 審核操作（核准/駁回）執行後無法撤銷
- 如有任何疑問，請先聯繫系統管理員，不要自行嘗試
